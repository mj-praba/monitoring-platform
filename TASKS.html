Blocking

stops an actual end-to-end demo cold

The backend's pairing/auth contract changed when it split into apps/ + packages/; the web and mobile clients were never updated to match, so pairing and live streaming don't work from either app today, as-is.

Frontend: capture the refresh token blocking ~2–3 hrs

POST /api/auth/register and /login now return { access_token, refresh_token, token_type } (backend/apps/api/src/auth/auth.service.ts:14-18), but frontend/src/api/client.ts's TokenResponse only declares access_token/token_type, and Login.tsx:17 only stores the access token. There's no refresh flow client-side at all.

Why: the access token is short-lived by design; without this, sessions silently die and users get logged out mid-demo.

Frontend: pairStart is missing a required locationId blocking ~3–4 hrs

POST /api/devices/pair/start requires auth (already sent) and a locationId body field (devices/dto/pair-start.dto.ts) — it 400s without one (devices.service.ts:50-52). client.ts:61 sends no body at all, and ConnectDevice.tsx has no location selection UI. Needs a GET /api/locations call, auto-selecting the single default location created at registration.

Why: this is the actual button click that starts a demo ("Connect Device") — it 400s immediately today.

Frontend + mobile: wrong default API/WS ports blocking ~15 min

Backend defaults: API PORT=8001, WebSocket WS_PORT=8002, two separate processes. frontend/src/api/client.ts:1-2 and mobile/src/services/api.ts:1-2 both default to port 8000 — a third port that matches neither. .env/.env.example already have the right values; this is just the hardcoded fallback constant.

Why: anyone running without a perfectly-set .env silently connects to nothing.

Frontend: stale Device response type blocking ~15 min

Backend's DeviceOut includes location_id, device_type_id, metadata (devices.mapper.ts:3-12) that client.ts:40-46's Device interface doesn't declare.

Why: not a runtime break today, but blocks showing a device's location/type without a silent type mismatch.

Run the Kafka pipeline live, end to end, at least once blocking ~30–60 min

The Redis→Kafka migration was verified with pnpm typecheck and docker compose config only — never actually run. Do: docker compose up -d kafka, pnpm dev:websocket + pnpm dev:ingestion-worker, then node scripts/simulate-device.js --code <code>; confirm the dashboard's Monitor page updates live and MongoDB receives device_metrics documents.

Why: depends on the frontend fixes above to even get a pairing code — do this last, as the final proof the demo works.

Verify docker compose up brings up the full stack cleanly blocking ~30 min

In this dev sandbox, the running clickhouse container reports unhealthy — its logs show get_mempolicy: Operation not permitted, which looks like a container-sandbox/seccomp restriction rather than a repo config bug, but needs confirming on a normal Docker install. backend-api's depends_on: clickhouse: condition: service_healthy means the whole stack won't start if this reproduces elsewhere.

Why: if this reproduces on a clean machine, nobody can docker compose up the project at all.

Deferred

real, but explicitly out of scope for "working demo"
AWS CD pipeline fails — OIDC role not authorized deferred

cd.yml's role assumption is rejected: Not authorized to perform sts:AssumeRoleWithWebIdentity. Nothing has ever actually deployed to ECS. This is an AWS IAM/OIDC trust-policy fix outside the repo, not something fixable in code.

No automated test suite anywhere deferred

Zero *.spec.ts/*.test.ts files across backend, frontend, mobile, or desktop. Valuable long-term; not required to demo the app manually.

Scoped RBAC is an "initial impl" deferred

A global (not per-tenant) permission catalog, route-convention scope resolution rather than a fully generic resolver. Documented and deliberate — see docs/ARCHITECTURE.md.

Desktop installers unsigned, no app icon deferred

Windows SmartScreen shows an "unknown publisher" warning; electron-builder falls back to a default icon. The desktop app is a separate, unrelated showcase — cosmetic.

Mobile CPU metric is a proxy, not a real percentage deferred

Android exposes no permission-free, root-free way to read true system CPU load — an OS-level constraint, not fixable by changing this codebase.
